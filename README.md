# Customer Segmentation, Retention Modeling, and Marketing Allocation

**MATH 167R — Project 3** · Zhanxiang (Joe) He · San José State University

Using the dunnhumby *Complete Journey* data to answer three questions for a retail company:

1. What kinds of customers do we have?
2. Which customers are likely to return and purchase again?
3. How should we allocate a **$1,000,000** marketing budget across them?

## Approach

| Step | Method | Script |
|---|---|---|
| 1 | Import full transactions; split Jan 1–Sep 30 (features) / Oct 1–Dec 31 (holdout); define `retained` | `R/01_import.R` |
| 2 | Build one row per household: recency, frequency, monetary value, basket size, discounts, product breadth | `R/02_features.R` |
| 3 | PCA on standardized behavior variables | `R/03_pca.R` |
| 4 | K-means for k = 2–6; elbow, silhouette, size, stability | `R/04_kmeans.R` |
| 5 | Profile clusters and assign business segment labels | `R/05_segments.R` |
| 6 | Logistic regression for return, evaluated on held-out households | `R/06_logistic.R` |
| 7 | $1M budget allocation | `R/07_budget.R` |

## Data

- Source: the [`completejourney`](https://cran.r-project.org/package=completejourney) R package (dunnhumby, 2017).
- Uses the **full** transactions (`get_transactions()`, 1,469,307 rows, 2,469 households), not `transactions_sample` (a random 5% of rows, which splits baskets apart).
- Unit of analysis: one household. 2,446 households purchased in the feature period. 94.2% returned in the holdout period.
- Demographics exist for 801 households only, so they describe segments and are not used to build them.

## How to reproduce

1. Clone the repository and open `customer-segmentation-project.Rproj` in RStudio.
2. Install packages: `renv::restore()` (or `install.packages(c("tidyverse", "completejourney", "cluster", "factoextra", "tidymodels", "car"))`).
3. Run the scripts in `R/` in numeric order from the project root. `01_import.R` needs internet the first time because `get_transactions()` downloads data from GitHub.
4. Render the report in Terminal:

   ```bash
   quarto render project3_report.qmd --output-dir docs
   ```

## Git structure

- Single `main` branch, one commit (or more) per analysis step, e.g. `Step 2: household features`.
- Scripts and small outputs are committed; large intermediate data in `data/` are ignored and can be rebuilt from `R/01_import.R`.
- The rendered report lives in `docs/` so GitHub Pages can serve it from `main /docs`.
